# 歌单迁移：开发约定

## 用户流程

选择来源歌单 → 选择目标音源 → 找歌 → 检查匹配 → 选择目标歌单 → 迁移 → 查看记录。

展示文案保持简短：`正在找歌`、`检查匹配`、`正在迁移`、`继续迁移`、`重试失败歌曲`。迁移不会删除或修改来源歌单。

## 任务与恢复

- 每个任务保存来源歌单快照和按原顺序排列的歌曲，避免来源歌单在迁移过程中变化。
- 每首歌曲分别保存候选结果、手动确认/跳过状态、目标歌曲 ID、写入结果；未确认的低置信度匹配不能直接写入。
- 读取分页、匹配、创建目标歌单、添加歌曲各阶段均必须保存检查点。失败只暂停当前阶段，重试时从检查点继续。
- 创建歌单发送请求前记录意图；收到成功后立即保存目标歌单 ID。如果创建请求超时且结果不确定，不允许直接再创建一个，应先在平台上核查或者让用户选中已创建的歌单。
- 添加歌曲请求结果不确定时不能盲目重发，应核对目标歌单。成功项不再写入；无法确定时要求用户处理，避免重复。
- 支持音源原生批量写入时保存每条结果；如果 API 只返回整批成功/失败且结果不明确，不能将整批当作失败并直接重试。
- 删除任务必须单独确认，不删除目标平台已创建的歌单。

## 平台后台限制

后台执行和持久化恢复是不同保证：桌面应用保持运行时可继续任务；Android 使用满足系统限制的持久任务调度；iOS 被系统挂起时不承诺持续执行，但前台恢复后可继续。

## 交付顺序

1. 可持久化的任务模型、分阶段执行及恢复测试。
2. 接入当前音源检索、歌单列表及写入能力；完善创建歌单结果和可选批量写入能力。
3. 接入各平台存储/任务调度与六个页面，最后用真实账号验证。

这是实现约定，不代表以上能力已经全部交付。
