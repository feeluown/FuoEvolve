# 歌单迁移

用户流程：选择歌单 → 选择目标平台 → 自动找歌 → 核对匹配 → 选择目标歌单 → 迁移 → 查看记录。

界面使用「正在找歌」「检查匹配」「正在迁移」「继续迁移」等简短文案。来源歌单始终不修改。

## 目标平台

- 仅展示支持向歌单添加歌曲的平台；匹配候选仅来自所选目标平台。
- 同时支持创建歌单与添加歌曲的平台，提供「创建并迁移」。
- 不支持在应用内创建歌单时，引导用户先在对应平台创建，再刷新并选择已有歌单。
- 创建结果不明确时不重复创建；用户核对后手动选择目标歌单。

## 持久化与恢复

- 保存来源歌曲分页快照、匹配候选和用户选择、目标歌单 ID，以及每首歌的写入状态。
- 分页读取、匹配、创建歌单和添加歌曲逐步落盘；中断后从持久检查点继续，不重新提交已确认成功的写入。
- 写入结果不明确时先重新读取目标歌单核对，不能盲目重发；失败记录和已成功歌曲均保留，可继续处理。
- 转换（读取、匹配）与目标歌单写入分成两个独立后台阶段。转换必须停在「检查匹配」，只有用户确认并选择或创建目标歌单后才开始写入。
- 阶段通知携带任务 ID：转换结束打开匹配检查，写入结束打开结果；暂停时保留恢复入口。过期或迟到的旧阶段任务不得跨过用户确认步骤。

## 平台后台能力

- **Android**：使用带网络约束的 WorkManager 长任务和前台数据同步通知；Android 13 及以上单独申请通知权限，拒绝权限不阻止迁移任务，但通知可能不可见。
- **iOS 26 及以上**：用户主动触发时使用 `BGContinuedProcessingTask`，可展示系统任务进度；用户或系统取消时保留可手动恢复的检查点。
- **旧版 iOS / 降级路径**：短时使用 `beginBackgroundTask`，剩余工作交由 `BGProcessingTask` 调度；多个待执行任务逐个续跑。具体执行时机由系统决定，不能保证挂起后立即运行或在固定时间完成。
- **Windows / macOS / Linux**：应用运行期间执行迁移，并通过 Nucleus 展示对应平台支持的原生进度及结果通知。关闭应用后保留检查点，重新进入可继续。

## 验证与交付

- 公共层测试覆盖恢复、重复写入保护、不明确结果核对、后台阶段和通知导航；新增目标平台创建能力判定测试。
- CI 执行 Android、iOS Kotlin/Native 与 Xcode App 编译，以及 Windows、macOS、Linux Nucleus 运行时测试；Android 还构建签名 APK。
- CI 成功不等于真实账号接口端到端验证。各平台登录、真实歌单创建/写入，以及前后台切换、系统终止、网络中断场景仍需设备实测。
- 批量写入仅在音源暴露并实现可靠批量接口时启用；当前不将逐首写入伪装为批量能力。
